## 4. Описание найденных дефектов

### DEF-001: Критический — Аварийное завершение приложения при делении на ноль

| Атрибут | Значение |
|---------|----------|
| **ID** | DEF-001 |
| **Заголовок** | Калькулятор аварийно завершает работу (crash) при попытке деления на ноль вместо отображения ошибки |
| **Серьезность (Severity)** | Critical (Критическая) — потеря доступности функции, нет обработки исключения |
| **Приоритет (Priority)** | High (Высокий) — базовая операция, должна быть исправлена в первую очередь |
| **Модуль** | Арифметическое ядро / Обработка исключений |
| **Версия** | Build 04.10.2026 |
| **Статус** | New (Новый) |
| **Назначен** | Разработчик / Команда разработки |

#### Шаги воспроизведения
1. Запустить `Calculator.exe`
2. Ввести делимое: нажать `1` `5` (или любое ненулевое число)
3. Нажать кнопку деления `÷`
4. Ввести делитель: нажать `0`
5. Нажать `=`

#### Ожидаемое поведение
Приложение должно перехватить исключение `DivideByZeroException` и отобразить пользователю понятное сообщение об ошибке:
- `Error` / `Ошибка`
- `Cannot divide by zero` / `Деление на ноль невозможно`
- `∞` (бесконечность)
- При этом приложение должно оставаться работоспособным (возможность нажать `C` и продолжить работу)

#### Фактическое поведение
Приложение **мгновенно закрывается** (process termination) без какого-либо диалога, сообщения в Event Viewer или записи в лог. Процесс `Calculator.exe` исчезает из диспетчера задач.

#### Доказательства
- Скриншот до нажатия `=` (экран показывает `15÷0`)
- Скриншот после — рабочий стол / отсутствие окна калькулятора
- В журнале событий Windows (Event Viewer → Windows Logs → Application) фиксируется событие `Application Error` с кодом исключения `0xC0000094` (STATUS_INTEGER_DIVIDE_BY_ZERO) или `0xE0434352` (CLR exception), если приложение на .NET

#### Влияние на пользователя
- Потеря несохранённых вычислений
- Непонимание причины закрытия (нет обратной связи)
- Необходимость перезапуска приложения

#### Root Cause (предположительно)
В коде обработки операции деления отсутствует проверка делителя на ноль **до** выполнения операции ИЛИ отсутствует блок `try-catch` вокруг деления, перехватывающий `DivideByZeroException` / `ArithmeticException`.

**Псевдокод проблемы:**
```csharp
// Плохо: нет проверки
result = operand1 / operand2;

// Хорошо:
if (operand2 == 0) {
    ShowError("Cannot divide by zero");
    return;
}
result = operand1 / operand2;
```

#### Рекомендация по исправлению
1. Добавить валидацию делителя перед выполнением операции деления
2. При обнаружении нуля — установить флаг ошибки на дисплее, заблокировать дальнейший ввод до нажатия `C`/`CE`
3. Покрыть юнит-тестом: `Assert.Throws<DivideByZeroException>(() => Calc.Divide(10, 0))` или проверку UI-состояния

### DEF-002: Незначительный — Отсутствие индикатора переполнения при умножении больших чисел

| Атрибут | Значение |
|---------|----------|
| **ID** | DEF-002 |
| **Заголовок** | При переполнении при умножении больших чисел не показывается явный индикатор (E/Overflow), результат просто переходит в научную нотацию |
| **Серьезность** | Low (Низкая) |
| **Приоритет** | Low |
| **Статус** | New |

**Описание:** При выполнении `99999999 × 99999999` результат `9.9999998e+15` отображается корректно, но пользователю неочевидно, что произошло переполнение разрядности экрана. В стандартном калькуляторе Windows при переполнении появляется метка `E` или переключение в научный формат явным образом.

**Рекомендация:** Добавить визуальный индикатор (суффикс `E`, смена цвета, tooltip) при переходе в экспоненциальную запись.
